# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

「簡易記帳」— a Windows personal-finance app (WPF, .NET 10, `net10.0-windows`) ported from an earlier Python/Tkinter version. Desktop project `ZZZ/ZZZ.csproj` (namespace `ZZZ`, but `AssemblyName` is `Ledger`, so the exe is `Ledger.exe`). There is also an Android version, `Mobile/Mobile.csproj` (see "Android version" below). All UI text and code comments are Traditional Chinese.

The repo has two remotes: `origin` = `asdZzz-coder/tools` (desktop releases) and `phone` = `asdZzz-coder/money-phone-app` (Android releases). Each release workflow runs only in its own repo (`if: github.repository == …`).

## Commands

Run from `ZZZ/` (the project folder):

```bash
dotnet build
dotnet run
```

Publishing (both are compressed single-file and self-contained, about 60 MB, so a PC without .NET runs them as-is; WPF's native DLLs are extracted to `%TEMP%\.net\Ledger` on first run):
- ClickOnce needs full Visual Studio MSBuild, not `dotnet publish`: `msbuild ZZZ\ZZZ.csproj -restore -t:Publish -p:PublishProfile=ClickOnceProfile -p:Configuration=Release`. The profile is `ZZZ/Properties/PublishProfiles/ClickOnceProfile.pubxml`, and the output goes to `ZZZ/bin/Release/net10.0-windows/win-x64/app.publish/`. Locally, MSBuild is at `C:\Program Files\Microsoft Visual Studio\18\Community\MSBuild\Current\Bin\amd64\MSBuild.exe`.
  - The bootstrapper is disabled, so there is no `setup.exe`. The installer zip contains `installer/安裝.cmd` (must stay CRLF, see `.gitattributes`), `Ledger.application` and `Application Files\`. `安裝.cmd` copies them to `%LOCALAPPDATA%\Ledger-Setup` and opens the `.application` from there, which avoids ClickOnce's "already installed from another location" error. To build it locally, copy those three items from `app.publish` into `dist\` and zip them (this is what the workflow's "打包 ClickOnce 安裝檔" step does). `ApplicationVersion` in the profile follows `<Version>`, so bump `<Version>` in the csproj for every package you hand out: ClickOnce won't replace an installed copy that has the same version.
  - Smart App Control (Windows 11) can silently block an unsigned `Ledger.exe` from the ClickOnce cache (Code Integrity event 3077 in `Microsoft-Windows-CodeIntegrity/Operational`; the app just doesn't open). Verdicts are per file content, so a rebuilt exe may pass where an earlier one didn't, but only a trusted code-signing certificate fixes it reliably.
- Portable exe: `dotnet publish ZZZ\ZZZ.csproj -c Release -r win-x64 -p:SelfContained=true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true`. `IncludeNativeLibrariesForSelfExtract` folds SQLite's `e_sqlite3.dll` and the WPF native DLLs into the exe. Without compression the exe is about 140 MB.
- Folder zip (`Ledger-Folder-vX.Y.Z.zip`): the same self-contained publish with `-p:PublishSingleFile=false`, zipped. The APP launcher (`asdZzz-coder/launcher`, its `apps.json` matches `^Ledger-Folder.*\.zip$`) downloads this one, because Smart App Control blocked the unsigned single-file `Ledger.exe` while a folder publish of the same code ran. Keep the `Ledger-Folder` prefix.

Releasing: pushing a `vX.Y.Z` tag (`git tag v1.2.0; git push origin v1.2.0`) runs `.github/workflows/release.yml` on the `windows-2025-vs2026` runner. It builds both packages with the version taken from the tag (`-p:Version` and `-p:ApplicationVersion=X.Y.Z.0`) and publishes them to a GitHub Release. ClickOnce auto-update is disabled because Release assets have no stable update URL. Instead, the in-app `Updater` polls the latest Release of `asdZzz-coder/tools`, which must stay public. For a ClickOnce-installed copy (`Updater.IsInstalled`) and a Release that has a `Ledger-ClickOnce*.zip` asset, it downloads the zip, copies it over the original install source folder (found via the `.appref-ms` shortcut, falling back to `%LOCALAPPDATA%\Ledger-Setup`) and opens `Ledger.application`, so ClickOnce treats it as an upgrade, then the app exits. For the portable exe or a dev run it just opens the Release page. The asset name must keep the `Ledger-ClickOnce` prefix. ClickOnce installs each version into its own `Apps\2.0\…\ledg..tion_*` folder and rewrites the `.appref-ms` shortcuts itself. A taskbar pin, though, is a `.lnk` to one version's `Ledger.exe`, so on startup `Updater.RetargetShortcuts` points such `.lnk` files (taskbar, desktop, Start menu) at the running version. ClickOnce keeps one previous version in its cache for rollback and removes older ones by itself; don't delete cache folders by hand.

There is no test project or linter. To run the app against throwaway data instead of the user's real database, set `LEDGER_DATA_DIR` before launching (PowerShell: `$env:LEDGER_DATA_DIR="C:\some\temp\dir"; dotnet run`). The build fails with a locked-file error if a `Ledger.exe` instance is still running.

## Architecture

- **Data compatibility is a hard constraint.** `Database.cs` uses the same SQLite file location (`%APPDATA%\Ledger\ledger.db`) and schema as the original Python app, so existing user data must keep working. Schema changes go in `Database.Init()` as additive `CREATE TABLE IF NOT EXISTS` / guarded `ALTER TABLE` migrations (see the `wallet_id` upgrade). Don't rename or drop columns. Amounts are `REAL`, dates are `TEXT` in `yyyy-MM-dd`, and record type / debt direction are stored as the Chinese literals in the `Database.Income/Expense/IOwe/TheyOwe` constants.
- **`Database`** is a thin wrapper over one `SqliteConnection`. SQL uses positional parameters `@p0, @p1, …` matched to the `params` args of `Exec/Scalar/Query`. Multi-statement writes use `InTransaction(...)`, which sets the `tx` field so every command it creates joins that transaction (Microsoft.Data.Sqlite requires this). Read models are C# `record`s (`RecordRow`, `DebtRow`, `GoalRow`, …) that hold computed display properties (`AmountText`, `Status`, `Hint`, …), and XAML binds to those directly.
- **No MVVM.** `MainWindow.xaml.cs` is code-behind. Each tab (`RecordsView` / `DebtsView` / `GoalsView`, switched by the `Tab*` radio buttons) has a `Refresh*()` method that re-queries the DB and resets `ItemsSource` and summary text. After any write, call the matching refresh. `ReloadEverything()` reloads all tabs and is used after an import. Sidebar wallets are ordered by `wallets.sort` (then `id`). Dragging an item in `WalletList` moves it live in the `ObservableCollection` and saves the new order with `ReorderWallets` on drop; 「全部錢包」 is a synthetic first item and stays on top. Savings-goal balances are separate from wallet balances. A goal whose `repeat` column is `Database.Yearly` is a yearly bill (car tax, insurance): its `deadline` is the next due date, and 「繳費」 (`PayYearly`) withdraws up to the saved amount and moves the deadline one year ahead.
- **Goals kept in a wallet:** `goals.wallet_id` (`GoalRow.Linked`) records which wallet holds a goal's money. Several goals can share a wallet, and their `goal_deposits` are allocations of its balance: a goal's saved amount is always the sum of its deposits. `WalletFree()` is the wallet balance minus every allocation. 存入, `GoalForm` (moving to another wallet) and `DepositEdit` refuse to allocate more than that.
  - **Sidebar:** shows 「未分配 X」 under the wallet (`WalletItem.AllocText`). It turns orange as 「分配超出」 when spending later drops the balance below the allocations.
  - **Yearly bills:** for a yearly bill kept in a wallet, 「繳費」 (`PayYearlyFromWallet`) records an expense in the wallet and withdraws only from that goal.
  - **Refresh:** after any goal or deposit change, call `RefreshSidebar()`, which also calls `RefreshGoals()`, so the allocation text stays current.
  - **Deleting the wallet:** `DeleteWallet` sets `wallet_id` back to NULL and the deposits stay.
  - **v1.0.9 upgrade:** in v1.0.9 a linked goal's saved amount *was* the wallet balance. `ConvertLinkedGoals()` runs once (guarded by `PRAGMA user_version` < 1) and adds a 「連結錢包時的餘額」 deposit so those goals keep the amount they showed.
- **Credit cards** are wallets with `wallets.kind = Database.CreditCard` (`Wallet.IsCard`), plus `closing_day`, `due_day`, `credit_limit` and `pay_wallet_id`, the wallet the bill is paid from. A card's balance is negative while money is owed (`Wallet.Owed`). Spending is an ordinary 支出 record on the card wallet.
  - **Paying the bill:** 「繳卡費」 always pays from the card's `pay_wallet_id`, which is changed only in 「編輯錢包」. The money moves only when the user confirms 「已繳費」 with the paid amount. The payment is a transfer to the card, not an expense, because the spending was already recorded (see Transfers below). The list labels it 繳卡費 (`TransferRow.ToCard`). When it is edited, only the date, amount and note change.
  - **Paying any time:** 繳卡費 works with no debt and for more than the debt. The excess makes the card balance positive: that is 溢繳 (`Wallet.Credit` / `CardBill.Credit`), which later spending uses up first. The sidebar and the hero card show 「溢繳 X」, and it adds to the available credit.
  - **Bill:** `Database.Bill` returns a `CardBill`. Everything up to and including the last closing date is the statement, and transfers in after that date pay it off. Spending after the closing date is 未出帳. The due date is the first `due_day` after the closing date. Days past a month's end clamp to the last day.
  - **Where it shows:** the sidebar line (`CardBill.Short`, orange when late). When a card is selected, the records view's hero card shows 本期應繳 and the 「繳卡費」 button (`PayCard_Click`).
  - **Installments (分期):** the hero card's 「分期」 button (`Installment_Click`) adds or manages an `installments` row (card, first-period date, category, amount, periods, annual `rate` %). Each period is a real 支出 record on the card with `records.installment_id` and `period`, dated one month apart from the first. So periods land in their own statements, the stats and the totals, while future periods still count in the card's debt and used credit (`CardBill.Future`, not 未出帳). `Installment.Schedule` amortizes with equal payments, so interest falls each period. The payment is floored to whole dollars and the last period takes the remainder. Editing a plan regenerates all its records. In the records list a period shows 「分期 3/12」 (`RecordRow.NoteText`). Editing a period opens its plan, and deleting a period deletes the whole plan.
  - **Editing:** 「編輯錢包」 converts a normal wallet into a card, or back. A wallet that holds savings goals, or that pays another card, can't become a card. Cards can't hold savings goals. A card with installments can't become a normal wallet, and deleting it deletes its plans.
- **Wallet kinds:** `wallets.kind` is `""` (normal), `Database.Savings` (存錢用錢包) or `Database.CreditCard`. 流動資金 (`MainWindow.Liquid`) is the sum of the normal wallets only, excluding savings wallets and cards. It shows under 「全部錢包」 in the sidebar (`WalletItem.Extra`) and on the hero card.
- **Transfers** (`transfers` table, 「轉移資金」 button, `Transfer_Click`) move money between non-card wallets. Cards only receive money through 繳卡費. A transfer can't take more than the source wallet's balance minus its goal allocations (`WalletFree`).
  - **Balances:** wallet balances include transfers in and out (`Database.BalanceSql`).
  - **In the list:** transfers appear in the records list as `TransferRow`, type 轉帳, category 轉移資金 or 繳卡費. They are excluded from the income and expense totals, the charts and the CSV export. Edit and delete in the list handle both row kinds.
  - **Deleting a wallet:** its transfers are rewritten as 其他 income or expense records on the other wallet, so that wallet's balance doesn't change.
- **Debts through a wallet:** `debts.wallet_id` (NULL = 「不經過錢包」) is the wallet a debt's money went through on its date. Lending (別人欠我) takes money out of it, and borrowing (我欠別人) puts money in. 記錄還款 can pick a wallet too, default the debt's own. A repayment with a wallet adds a `debt_payments` row (date, wallet, amount) as well as raising `debts.paid`, while one without a wallet only raises `paid`, as 標記還清 and editing 已還金額 do. Cards can't be debt wallets, and a wallet with debts can't become a card. Money going out (lending, repaying what I owe) is checked with `CheckOutflow`, like transfers.
  - **Balances:** `BalanceSql` adds both. The repayment sign comes from the debt's current direction, so editing the direction flips its payments too.
  - **In the list:** `db.DebtMoves` lists them in 收支記錄 as `DebtMoveRow` (type 欠款, category 借出/借入/收回還款/還款). Like transfers, they are not counted as income or expense. Editing a loan row opens 編輯欠款, and a payment row can change date, wallet, amount and note. Deleting a loan row is refused, while deleting a payment row subtracts it from `paid`.
  - **Deleting:** deleting a debt deletes its payments, which restores the wallet balances. Deleting a wallet sets `debts.wallet_id` to NULL and drops its `debt_payments`, keeping `paid`.
- **支出圖表 tab** (`StatsView`, `RefreshStats()`) is read-only, so it recalculates only while visible: when the tab is shown, and at the end of `RefreshRecords()`, which runs on wallet changes and after writes. It follows the sidebar wallet and has its own period, `statsPeriod`: `yyyy-MM`, `yyyy` or `""` for all. `db.Records(prefix, …)` matches on a `LIKE prefix%` date, so a year prefix works too. Records' `MonthBox` also accepts `yyyy`.
  - The charts in `Charts.cs` are drawn with WPF shapes, with no chart library: `DonutChart` for expenses by category and `MonthBarChart` for 12 months from `db.MonthTotals`.
  - Each month column is a `ChartColumn`-styled `Button` whose automation name is `yyyy-MM`.
  - Clicking a category, in the donut or in the `CatLegend` list, calls `ShowCategoryRecords`. That sets `catFilter`, switches to 收支記錄 with the same period, and shows a removable chip. `FilteredRecords()` applies `catFilter` for the list and for the "目前篩選" CSV export.
  - Category colors come from `ChartPalette`, keyed by the category's order in 管理分類 so they stay stable across periods. The palette is muted and avoids green, red and orange, which keep their income, expense and overdue meanings; 「其他」 is always gray.
- **Import/export** lives in `DataTransfer.cs`:
  - The JSON full backup is a generic dump of every table listed in `Database.Tables`. Importing it replaces all data via `Database.ReplaceAll`, which accepts only known tables/columns, and `AutoBackup` (`VACUUM INTO`) saves the current data first. **A new table must be added to `Database.Tables`** or it won't be backed up.
  - 「刪除全部資料」 (`ClearAll_Click`) asks twice: a danger `Confirm` listing the counts, then a `Prompt` where the user must type 「刪除」. It first writes a JSON backup with `DataTransfer.SafetyBackup` to the `Backups` folder (restorable via 匯入資料), and deletes nothing if that fails. `Database.ClearAll` empties every table and leaves the default 「現金」 wallet and categories.
  - CSV import appends records, auto-creates missing wallets/categories, and falls back to Big5 when the file isn't valid UTF-8.
- **Dialogs**: don't use `MessageBox`. Use the static helpers on `DialogWindow` (`Info/Success/Error/Confirm/Prompt/Choose`). `Prompt` takes `Field[]` and an optional validator that returns an error string, so the dialog stays open on invalid input. Its optional `preview` callback recalculates a text box under the fields on every change (the installment form uses it to show each period's amount). A `Field` with `IsDate: true` is a TextBox plus a calendar-popup button, not a `DatePicker`: `DatePicker` silently clears a mistyped date on lost focus, so the typed text would never reach the validator. A `Field` with `Options` is a non-editable ComboBox whose value is the selected string. The record edit dialog packs type and category into one `支出 · 餐飲` option so a single dropdown covers both. While a dialog is open it dims `MainWindow` via `SetDim`.
- **Light/dark theme**: brushes live in `Colors.Light.xaml` and `Colors.Dark.xaml`, which must define the same keys. `App.xaml` merges one of them first and then `Themes.xaml`.
  - **Switching:** `App.SetTheme` swaps that first merged dictionary. 「深色模式/淺色模式」 in the sidebar calls it, and the choice is saved to `theme.txt` in `Database.DataDir`. The first run follows Windows' `AppsUseLightTheme`.
  - **XAML rule:** always reference brushes with `{DynamicResource …Brush}`, never `StaticResource`, or they won't change on a switch.
  - **Code rule:** code that sets a color uses `SetResourceReference`, or `FindResource` inside a `Refresh*` method that `ToggleTheme_Click` re-runs.
  - **No hard-coded light colors:** don't use `White` or `#…` literals except on the always-dark `HeroBrush` cards. Text on `InkBrush` uses `OnInkBrush`, because ink flips to light in dark mode.
  - **Exception:** the date field's calendar popup intentionally stays white, since the default `Calendar` style is light-only.
- **Styling**: everything is in `Themes.xaml` (merged in `App.xaml`). Use its brush keys (`InkBrush`, `IncBrush`/`ExpBrush` for income/expense, `*SoftBrush` backgrounds) and named styles (`AccentButton`, `GhostButton`, `OutlineButton`, `DangerButton`, `IconButton`, `Card`, `Pill`, `Segment`, `TabRadio`, …). The color rule: the chrome is ink/grayscale, and color is reserved for meaning (green = income/achieved, red = expense/danger, orange = overdue). Icons are glyphs from `Segoe Fluent Icons`/`Segoe MDL2 Assets` via the `Icon` TextBlock style. The app icon (`Assets/AppIcon.ico` for the exe, window and ClickOnce shortcuts; `AppIcon.png` for the sidebar logo) is drawn in code by `ZZZ/Assets/make-icon.ps1`. Edit that script and run it with Windows PowerShell 5.1 (`powershell -File ZZZ\Assets\make-icon.ps1 -Preview preview.png`) rather than editing the images. The script must keep its UTF-8 BOM, or 5.1 misreads the Chinese comments. Implicit styles restyle `TextBox` (its `Tag` is placeholder text), `ComboBox`, `DatePicker`, `DataGrid`, and `ScrollBar`.
- **Culture**: `App.OnStartup` sets a zh-TW culture whose `ShortDatePattern` is `yyyy-MM-dd`, so `DatePicker` and parsing use the DB date format. Amounts are parsed with `DialogWindow.TryParseAmount` (invariant culture, commas allowed).
- **Updates**: `Updater.cs` checks GitHub Releases. The current version comes from the assembly version: `<Version>` in the csproj, overridden by CI from the tag.

## Android version (`Mobile/`)

.NET MAUI, `net10.0-android` only (namespace `ZZZ.Mobile`, package `com.asdzzzcoder.ledger`). It is the same app with every desktop feature, rebuilt for a phone; the data on the phone is separate from the desktop's, and the two exchange data through the JSON full backup.

- **Shared code:** `Mobile.csproj` compiles `ZZZ/Database.cs` and `ZZZ/DataTransfer.cs` as linked files, so schema, business rules and backup format are identical. Keep those two files free of WPF types. Shared helpers live there (e.g. `Database.TryParseAmount`; `DialogWindow.TryParseAmount` just forwards). `DataTransfer` calls `Updater.CurrentVersion`, so the mobile `Updater` is in namespace `ZZZ`.
- **Data location:** `MauiProgram` sets `LEDGER_DATA_DIR` to `FileSystem.AppDataDirectory/Ledger` before `Database` is first used.
- **UI is built in C# (no XAML), no MVVM.** `Ui.cs` has the element factories and `Theme.cs` the colors: the same light/dark palette as `Colors.*.xaml`, as `Pair(Light, Dark)` bound with `SetAppThemeColor`. Values computed in code use `Pair.Now` and are recomputed in `Refresh()`, which also runs on `RequestedThemeChanged`. The theme choice (跟隨系統/淺色/深色) is saved to `theme.txt`.
- **Pages:** `AppShell` has five tabs (`RecordsPage`, `DebtsPage`, `GoalsPage`, `StatsPage`, `MorePage`, all `TabPage`). Pages opened from a tab (`WalletsPage`, `CategoriesPage`, `DepositsPage`) derive from `SubPage`, which draws its own `‹ 標題` bar: Shell's nav bar leaves a dark strip under the status bar on Android 15. `State` holds what the desktop `MainWindow` kept in fields (`SelWallet`, `Month`, `CatFilter`, `StatsPeriod`); every write calls `State.NotifyChanged()` and the pages re-query.
- **Operations** (`Ops.*.cs`) are ports of the desktop `_Click` handlers with the same validation and messages. Keep the two in sync when rules change.
- **Dialogs** (`Dialogs.cs`) mirror `DialogWindow`: `Info/Success/Error/Confirm/Prompt/Choose`, plus `Menu` (native action sheet) for per-row actions. A dialog is a transparent modal page. Its result is set only after it has been popped, and `OnDisappearing` counts as cancel only when it wasn't closed by a button. Taps go through `Ui.Run` (one operation at a time); buttons inside a dialog pass `guard: false`. A date field is an `Entry` with an invisible `DatePicker` over the calendar icon. Adding a record has its own full page (`AddRecordPage`, with 「再記一筆」 to keep entering).
- **Charts** are `IDrawable`s in a `GraphicsView` (`DonutDrawable`, `MonthBarsDrawable`). The first tap on a slice highlights it; tapping it again, or tapping a legend row, opens 收支記錄 filtered to that category.
- **Wallet style:** `wallets.style` is `''` (一般) or `Database.Cute` (可愛). The column is added in `Database.Init` and the desktop ignores it. A cute wallet gets a pastel card in `WalletsPage`, a pink gradient hero card in `RecordsPage` and animal icons (`Theme.CuteIcon`). Set it from the wallet's 「⋯ → 設定風格」.
- **Build / run locally:** the Android SDK is at `%LOCALAPPDATA%\Android\Sdk` and the JDK at `%LOCALAPPDATA%\Android\jdk`. Pass them as `-p:AndroidSdkDirectory=… -p:JavaSdkDirectory=…`. Build a Release APK with `dotnet publish Mobile\Mobile.csproj -f net10.0-android -c Release -o dist\android` (Release outputs an `.apk`, not an `.aab`). The emulator AVD is `ledger35`. When testing with `adb shell input text`, Gboard treats the input as a hardware keyboard and dims the screen; that is an emulator artifact, not an app bug.
- **Release:** pushing a `vX.Y.Z` tag to `phone` runs `.github/workflows/android-release.yml`. It publishes `Ledger-Android-vX.Y.Z.apk`, with `ApplicationVersion` (versionCode) = X*10000+Y*100+Z. The APK must always be signed with the same key, or an update can't install over the old version. The key is `%USERPROFILE%\.android-keys\ledger-release.keystore` (alias `ledger`, password in `ledger-release-password.txt` next to it), and it's stored in the repo secrets `ANDROID_KEYSTORE_BASE64` / `ANDROID_KEYSTORE_PASSWORD`. Never regenerate it. In-app 「檢查更新」 (`Updater`) reads the latest release of `asdZzz-coder/money-phone-app` and opens the APK link in the browser. Keep the `Ledger-Android` asset prefix.
